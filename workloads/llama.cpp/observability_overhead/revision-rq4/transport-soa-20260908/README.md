# transport-soa.patch — device-only mode-3 transposed ring writer

Latest status, 2026-09-08: this device patch is the bounded writer that
completes the record-preserving transposed ringbuf transport. It applies
cleanly against `241872b` of
`/home/yunwei37/workspace/gpu/bpftime-auto-warp` and was integrated with the
companion `host-transport-soa.patch` into runtime commit `886b4ca`. Neither
patch had been applied alone before that integration; the follow-up
`bpftime-agent`/`bpftime-syscall-server` build (with the existing trampoline
regeneration ON) completed successfully. `build-runtime.log` records both
targets reaching completion. Performance is **not yet measured**.

## Requires the companion host patch

This device patch alone does not make mode 3 usable. It writes the
transposed layout; the host reassembly in `host-transport-soa.patch` reads it
back into `local_buffer` before the unchanged record callback. Apply both
before any mode-3 build or run. The two sides agree on the same constants:
packed 24-byte headers, `payload_base = thread_count * 24`,
`word_stride = thread_count * 8`, `record_words = record_stride / 8`,
`record_stride = align8(8 + value_size)`, word 0 = payload size, errors at
`thread_count * entry_size`.

## Selection (opt-in)

`BPFTIME_GPU_RINGBUF_TRANSPORT=3` is opt-in under the existing auto-warp
environment convention (non-empty `BPFTIME_GPU_AUTO_WARP_EXECUTION` other than
"0") and is fixed at map construction. The device reads the stored level
through `map_info.batch_output`; the level value is chosen by the host
`nv_gpu_ringbuf_map_impl` constructor and propagated to the device map-info
upload through the existing `get_output_transport()` chain.

## Mode 3 device writer (mirrors host-transport-soa.patch)

The writer is a new `batch_output == 3` branch inside
`_bpf_helper_ext_0025` in
`attach/nv_attach_impl/trampoline/default_trampoline.cu`. For the calling
thread `tid` and slot `s = tail % max_entries`, word `w`:

- Packed header: `extra_buffer + tid * 24` (existing 24-byte
  `ringbuf_header`, stride 24 instead of `entry_size`).
- Payload base: `extra_buffer + n * 24`, where `n = max_thread_count`.
- Transposed word position:
  `payload_base + ((s * record_words + w) * n + tid) * 8`.
- Word 0 carries `data_size` (payload size); words `1..record_words-1` carry
  the payload. The source is read byte-wise, so an unaligned payload and a
  trailing partial word are copied exactly and the destination word is
  zero-padded to 8 bytes. The host copies exactly `size` payload bytes and
  never reads the padding.
- Errors: `extra_buffer + n * entry_size` (unchanged offset).

The transposed region spans `[n * 24, n * entry_size)` and the total
allocation `n * entry_size + sizeof(ringbuf_error_counters)` is unchanged, so
the existing allocation, `record_stride`, and `entry_size` values are reused.

For a fixed slot and word, the thread-major stride is one 8-byte word, so
adjacent thread ids write adjacent 8-byte locations. This is a
record-preserving layout change only; it makes no claim about warp-level
record collapsing, and the hardware-traffic effect is unmeasured.

## Unchanged semantics

- Modes 0/1/2 keep their existing layout and byte-for-byte behavior.
- Encoded dirty publication is retained: `dirty >> 1` = published tail, odd
  word = in-progress producer; same head read, acquire/release rules, and
  per-thread callback order as the encoded-release mode.
- Exact records preserved: every per-thread record (80-byte or general
  `value_size`), all capacities, and all return/drop semantics are retained;
  there is no sampling or one-event-per-warp substitution. The original
  `bpf_perf_event_output` (helper 25) remains per-thread and per-event;
  mode 3 is a transport/layout change, not a whole-program leader lowering.
- The pre-branch validations are unchanged: out-of-range `tid` ->
  `oob_drops`/return 1, `data_size > value_size` -> `bad_size_drops`/return 3,
  `data_size != 0 && data == 0` -> `other_drops`/return 4. A lost
  `dirty`-word CAS and an odd pre-lock word both drop with `other_drops` and
  return 4, exactly as the encoded-release mode does.
- `BPF_PERF_EVENT_GPU_WARP_ONLY_OUTPUT` (flags bit 63) is handled identically
  before the mode dispatch and is not altered by this patch.

hash check was added.

## Runner exposure (source-only)

The runner exposes mode 3 through `--auto-warp-transport 3`, which sets
`BPFTIME_GPU_RINGBUF_TRANSPORT=3` for the loader and client. Until the host
and device patches are applied, built, and measured, mode 3 stays inert and
the default transport level remains 1.
