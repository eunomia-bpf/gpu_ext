**Independent review of `pipeline/completion-fence.patch` (applied in parallel by implementation; not authored by this consultation).**

**Verdict: sound, minimal, fail-closed.** Correct change set: `idle_policy.h/.c` (+`lp_outstanding`/`lp_inflight_bound`, strict validation), `pipeline_events.h` (host ring, ≤2 slots), `idle_executor.*` (ring lifecycle, ctor bound, report), `hummingbird_client.cpp` (`--lp-inflight-bound 1|2`, SETUP record), `Makefile` path split (HB_SOURCE read-only, HB_OUTPUT=pipeline/build), tests only. Published source/build/raw untouched; `995bc62` copies + patch-apply checks satisfy provenance.

**Hazards found (all narrow):**
1. `lp_gpu_done == (lp_outstanding==0)` validation is the load-bearing invariant. It holds only because both come from one `retire_completed()` call. Any future second source errors—good, but document it.
2. `next_slot()` throwing after policy allows launch is unreachable given `lp_outstanding <= bound` validation, but a bound>2 path would silently corrupt slot modulo arithmetic; the ctor's 1/2 rejection is the actual guard—keep both.
3. Bound 2 raises post-HP-publish in-flight LP work from 1 to 2 pieces. HP-stop ordering is preserved (same admission lock, `hp_pending` checked first), but LC protection cost is a measured consequence, not a bug.
4. `shutdown()` leaking events if `synchronize()` throws is pre-existing; ring doubles the count, doesn't create it. Don't scope-creep a fix here.
5. `run_request()`'s new "previous drain" guard plus `while (!done())` correctly drains all slots before completion.
6. Same-stream ordering and exact-once `GridCursor`/nop semantics unchanged—verified by inspection; no replay possible.

**Tests adequate.** 1,048 actual-JIT parity cases now include bound-2 overlap, full-ring wait, tick-before-bound, HP-stop precedence, bound 0/3 and `lp_gpu_done`/outstanding mismatch rejection. `test_pipeline_events` proves reuse-after-retirement, FIFO retirement order, query-failure propagation, drain, peak==bound, and `overlap_launches>0` iff bound 2. Add one negative case: bound-2 launch attempt with `kernel_unstarted=0` consolidation race.

**Runner integration — no framework rewrite.** Import the published `run_study`/`analyze_study`, then rebind module-global `HERE` to `pipeline/`. `measurement`, `config`, `execute` (leases, safety, telemetry, binary inventory, cleanup) and `parse_client`/`paired_comparison`/`expected_config` reuse verbatim; `expected_config` still matches since only the command changes. Add `fence_engagement`/`fence_orders`/`audit_fence_cell`/`analyze_fence` (~120 lines) asserting `configured_lp_inflight_bound`, issued==retired, zero outstanding at report, `overlap_launches` consistent with bound, and bound-1 cells reproducing the frozen `event-query-before-next-launch`/`max_lp_inflight==1` validators. `prepare.py` must additionally supply `arrivals-burstgpt.json`, `build/resnet152-split/mod.cubin` (`cp -p`, never nvcc), `fixed_client` and `hummingbird_profile` for `execute()`'s inventory. Four cells (C/BPF × 1/2) × two frozen arrivals × five 60 s blocks = 40; seed 20260903; no depth/profile retuning on outcome.

**Limitations.** The paper's figure is a **1.3% relative slowdown**, not 1.3 µs; nothing here measures microseconds. Host outstanding event records are issued-but-unretired launches—not hardware device-queue depth, and no preemption latency may be inferred. The prior 19–20% idle-vs-fixed gap must not be causally attributed to this fence; this ablation only tests whether relaxing it changes the outcome on this frontend. CPU checks are preparation, not results. Real preflight/full runs remain root-admitted, exclusive, and unstarted.
