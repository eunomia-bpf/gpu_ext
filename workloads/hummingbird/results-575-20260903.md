# Hummingbird idle scheduling — in progress

The real split-model calibration and isolated foreground reference passed.
The 20-cell small-pattern qualification passed independent raw audit; only the
output-copy pattern qualified. The five-arm, 50-cell performance comparison has
**not** completed. No throughput recovery or
native/BPF performance equivalence is established yet. The subsequent ten-cell
real-GPU preflight also completed; it remains excluded from formal estimates.

## Completed calibration

The source/runtime was prepared at gpu_ext commit `0cdec98`, on the same
RTX 5090 / Linux 6.15.11 / NVIDIA 575.57.08 / 400 W host as GPreempt.
Other compilation was paused and the runner held both shared experiment leases.
No driver or service was changed.

- [Real kernel/copy profile](raw/profile-575-01/profile.json): 308 runtime
  operations, including the executor's no-op copy, profiled using complete
  ResNet152 passes and occupancy-based capacity search. All 23 ResNet152 and
  102 VGG19 calibration outputs matched the isolated reference, maximum
  absolute error zero. The recorded source launch list has 307 entries; the
  runtime's additional operation is retained, not dropped from execution.
- The median measured launch cost is 1,298 ns. The frozen large-bubble threshold
  is 24,108 ns, derived from isolated copy/sync durations by the planned rule.
  Those measurements do not establish safe small-bubble admission; the initial
  profile has both small patterns disabled pending the separate comparison.
- [Isolated foreground cell](raw/isolated-lc-575-01/isolated-lc/result.json):
  all 6,000 periodic 100 requests/s arrivals completed and passed numerical
  checks inside the 60-second window, with no backlog. Scheduled-arrival to
  synchronized, verified output p99 is **1,811,879 ns**, frozen as the common SLO.
  Warmup/calibration adds 110 checked outputs, excluded from that p99.

Both runs exited successfully, passed telemetry and GPU/struct-ops cleanup,
and retained raw requests, commands and explicit binary inventories. These are
calibration dependencies, not performance comparison samples.

## Small-pattern qualification

All 20 cells (four variants, five randomized paired 10-second blocks) passed
[independent raw audit](raw/small-pattern-575-01/independent-audit.json), with no
missing, rejected or unexpected attempts. Every foreground request completed
correctly inside its window. The separate [selection record](raw/small-pattern-575-01/small-pattern-results.json)
retains all variants, including ineligible ones.

- Output-only qualified: real output-pattern launches occurred in every block;
  its paired LC-p99 ratio against no small patterns was 0.96859, 95% interval
  [0.91917, 1.00252], below the predeclared 1.01 upper-bound limit.
- Input-only and both were ineligible: neither observed an actual input-pattern
  launch. This is not successful input-bubble filling, even where latency was
  similar. No cell was rerun or dropped to change that outcome.

The [selected profile](raw/small-pattern-575-01/profile-selected.json) enables
output only. This qualification is an incremental-interference check on this
frontend, not a throughput benefit or a final C/BPF comparison. The shared
executor conservatively waits for each LP launch's completion event before
issuing the next; that differs from the paper's predicted pipeline.

## Real five-arm preflight

All ten 10-second cells completed: two arrival cases and five arms, with the
same selected profile, numerical checks, telemetry and cleanups. All 5,460
offered foreground requests finished correctly inside their windows. The
BurstGPT preflight preserves the first ten seconds of the frozen trace (92
arrivals); it does not compress the full 6,000-arrival trace into ten seconds.

Actual host-BPF JIT decision counts were 32,304,292 for periodic arrivals and
30,319,590 for BurstGPT. Every recorded BPF decision used the JIT; C cells
recorded zero JIT calls. Request, CTA and no-op-copy counts were retained in
the [raw cells](raw/preflight-575-01/completed-cells.json).

The short observations do **not** show a background-throughput recovery over
fixed GPreempt. That is not a reason to discard the cells or weaken correctness.
The full comparison must quantify the cost and foreground tradeoff. Shared
completion/pacing work is a candidate explanation, not a measured causal
breakdown: event-wait counters overlap HP-stop and tick-wait conditions.
