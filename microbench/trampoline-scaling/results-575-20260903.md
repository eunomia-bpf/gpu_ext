# RTX 5090 device-trampoline scaling result

Date: 2026-09-03. Hardware: one NVIDIA GeForce RTX 5090. Driver:
575.57.08. The authoritative raw records are
[`raw/preflight-575-04/`](raw/preflight-575-04/) and
[`raw/full-575-01/`](raw/full-575-01/).

## Completion and correctness

The repaired three-arm preflight completed, followed by all ten randomized
paired blocks. All 30 full-campaign arm processes and all 270 cell
measurements are valid. Every arm checked 1,048,576 output values per cell
with zero mismatches. Each attached process observed exactly 32 marker
callbacks, the counter arm's complete map matched the independent per-thread
oracle, and the logs show the required target-stub then marker-fallback
transformation. Every attached process detached both links. The final state
has no compute process, no struct-ops object, no Xid or new kernel anomaly,
and an NVIDIA UVM reference count of zero.

The preceding failure was real but was a harness-routing error: the runtime
assigns the module-wide explicit stub to the first attached program, whereas
the old loader attached the marker first. The repaired loader validates the
two program names and sections and attaches target then marker. The separate
marker and target-map oracles were not relaxed.

## Result

With active work fixed at 2,048 warps, increasing the launched grid from 256
to 4,096 blocks did not increase attached absolute time: the median no-op
times stay within 0.0329--0.0347 ms and the median counter times within
0.0537--0.0588 ms. The paired increment falls as native time grows from the
cost of surplus threads taking the common early-return path. Thus this tested
range shows no additional block-footprint scaling penalty once active hook
work is fixed.

With launch geometry fixed at 4,096 blocks, the return-only handler adds only
0.0012--0.0022 ms as active work grows from 2,048 to 32,768 warps. In
contrast, the per-thread counter increment grows from 0.0204 to 0.5417 ms;
from 4,096 to 32,768 active warps, an 8x increase, it grows from 0.0668 to
0.5417 ms, approximately 8.1x. The state-update body, rather than launched
block count alone, is therefore the visible scaling cost in this experiment.

Percentage overhead is large for the shortest cells because the native
denominator is only about 0.016--0.034 ms. The absolute increments above are
the more useful mechanism-scale quantities. Complete per-cell medians and
paired-bootstrap intervals are in
[`raw/full-575-01/summary.md`](raw/full-575-01/summary.md).

## Claim boundary

This result supports a bounded statement for the selected RTX 5090 runtime:
the minimal return-only hook has low absolute incremental latency and no
observed block-footprint trend over the tested range, while a handler that
updates per-thread map state scales with active work. It does not establish a
constant cost for arbitrary handlers.

The audited runtime inserts an ordinary PTX `call`/`call.uni`; it does not
implement or prove once-per-warp dispatch. The experiment is a synthetic
kernel microbenchmark, excludes attach and compilation time from CUDA-event
timing, and uses a runtime build with device verification disabled. It is not
an application-throughput result or strict-verifier-enforcement result.
