# Device-verifier A1-575-01 (retained failed attempt)

This RTX 5090 attempt correctly stopped during the first A0 STRICT cell, before
any A1 pair. The baseline reproduced the exact 47-byte correctness output. The
real `kernelretsnoop` object then completed successfully with the same output,
720,896 expected probe events, the complete launch/coordinate oracle, zero
drops, clean teardown, and all GPU safety gates passing.

The target process recorded exactly one STRICT acceptance for the expected
60-instruction `cuda__retprobe` program and exactly one matching map descriptor,
but it did not record `verification_elapsed_ns`. Therefore the A0 admission
gate failed and the runner retained `status: invalid_a0`; this attempt contains
no admission-latency or paired-performance result.

The cause was a stale runtime build. The verifier timing implementation was
present in `attach/nv_attach_impl/nv_attach_impl.cpp`, last modified at 05:45,
while the selected agent and syscall-server libraries were still the builds
from 05:06. The old agent contained the STRICT acceptance marker but not the
new timing marker. This is a build-freshness failure, not a verifier rejection
or a device correctness failure.

The failed directory is retained unchanged. The follow-up changes add a
pre-execution binary-contract gate and require a rebuilt runtime before a fresh
campaign uses a new output directory.
