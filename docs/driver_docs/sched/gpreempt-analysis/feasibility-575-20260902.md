# GPreempt on 575 / Linux 6.15 / RTX 5090: comparison feasibility

As of 2026-09-02, a formal comparison is **feasible as a porting project, not
ready to run**. The published userspace policy must retain its timeslice yield,
GDRCopy signaling, and hint-based pre-preemption. Our existing timeslice BPF
program is an analogue, not a reproduction of the complete mechanism.

This inspection was CPU-only: no GPU workload, ioctl, module installation,
driver change, or service change was performed.

### Safety and correctness issues to resolve during the port

- The added query case ends at [driver.patch:103](https://github.com/thustorage/GPreempt/blob/249ee3e/patch/driver.patch#L103)
  without `break` or `return` before `NV_ESC_RM_FREE`. This is a real fallthrough,
  but **not evidence that it actually frees a TSG**: the official
  [550.120 handler at escape.c:430](https://github.com/NVIDIA/open-gpu-kernel-modules/blob/550.120/src/nvidia/arch/nvalloc/unix/src/escape.c#L430)
  checks the FREE argument size before freeing. `OP_QUERY` encodes 32 bytes
  (`include/gpreempt.h:104`), whereas `NVOS00_PARAMETERS` is 16 bytes. The
  expected consequence on that path is an invalid-argument return.
- [NvRmQuery at gpreempt.cpp:46](https://github.com/thustorage/GPreempt/blob/249ee3e/src/gpreempt.cpp#L46)
  ignores the syscall return and reports only the output status; `NvRmControl`
  does the same at line 29. Zero-initialize arguments, check both returns, and
  reject absent/ambiguous context matches. A printed PASS alone is insufficient.
- [driver.patch:115](https://github.com/thustorage/GPreempt/blob/249ee3e/patch/driver.patch#L115)
  replaces general `Nv04ControlWithSecInfo` with `Nv04Control`. Do not carry this
  broad security-context bypass into a shared driver. Export only the needed
  owned-context operations with explicit checks; document this transport change
  without changing the scheduling decisions.
- The global `g_clientOSInfo`, exact-eight-channel assumption, and unchecked
  channel-array population in the new query need ownership/bounds checks. These
  are inspection findings, not reproduced failures on a GPreempt 575 module.
- [test-basic.cpp:51](https://github.com/thustorage/GPreempt/blob/249ee3e/src/tests/test-basic.cpp#L51)
  frees an aligned interior device pointer and treats a GDR mapping as a CUDA
  host allocation. Use the original allocation address and GDR unmap/unpin/close
  for the port's finite smoke cleanup. Preserve the upstream result separately.

## Mechanism that the original-policy cell must preserve

1. **Timeslice yield:** `src/gpreempt.cpp:61` sets LC (priority 0) to
   1,000,000 µs and BE to 1 µs. `NvRmPreempt` exists, but the main
   `gpreemptclient` does not call it as its primary scheduling mechanism.
2. **Context placement:** `gpreemptclient.cpp:169` creates/shares one CUDA
   context per role, then launches each role's streams in the matching context.
3. **Pre-preemption:** lines 204–217 enqueue a daemon hint for
   `preprocess_time - 100 µs`; lines 286–288 submit the blocking kernel when the
   hint becomes due. Reject preprocessing durations below the offset or define
   a documented bounded behavior; do not silently wrap unsigned arithmetic.
4. **Blocking kernel and signal:** lines 74–80 launch `gpu_block` twice, each
   with one thread, and signal through CPU-mapped GPU memory. `src/block.cu:2`
   spins on a volatile flag. Lines 234–240 enqueue inference, release the flag,
   then synchronize. GDRCopy at lines 83–112 is integral to this published path.
5. **Same input/copy/graph behavior:** retain the same executor, graph setting,
   preprocessing, arrivals, models, and request accounting in compared cells.

Local GDRCopy headers and userspace library exist under `/usr/local`, but
`/dev/gdrdrv` was absent at inspection. Header/library availability is not proof
that GPU memory pin/map works. No GDRCopy device was opened in this inspection.

## Three-way comparison and execution sequence

| Cell | Actual mechanism | Claim allowed |
|---|---|---|
| Baseline | Original `src/common-clients/baseclient.cpp`, native CUDA stream priorities, same workload/config | Original artifact's native non-context-preemptive baseline, not an unqualified “no-priority” baseline |
| Original GPreempt-575 port | Original client, role contexts, yield timeslices, GDRCopy flag, hint daemon, and block kernel; narrow documented compatibility fixes | Reproduction of the original mechanism on a new platform, once correctness and actuation pass |
| BPF policy | Same workload and semantic hint feed; explicit role-to-TSG mapping; BPF selects/applies equivalent scheduling actions | BPF port only for preserved components; if hints/blocking are omitted, label it a different policy/analogue |

Keep the optional `gpreemptclient_wo` (timeslices without pre-preemption) as an
ablation; a dual-context native ablation can additionally isolate topology
cost, but must not replace the upstream single-context/stream-priority baseline.
Use one 575 driver image exposing both required original operations
and BPF hooks if possible, with inactive mechanisms detached in other cells.
Changing drivers between cells otherwise becomes an explicit confound.

The minimal BPF bridge marks role/cookie **before** `cuCtxCreate`, lets task-init
read a bounded pending `(pid, tid)` role, then confirms the resulting context to
`(gpu, hClient, hTsg, generation)`/TSG association through a checked registration
operation. Track context create/set/push/pop/destroy, daemon execution, lazy
internal threads, multiple TSGs, and handle reuse; a post-create-only mapping
needs validated late control because the existing setter is init-time.
Explicit `hint_submit(cookie, stream, signal, deadline, sequence)` and
`infer_enqueued` events can drive a bpftime **host JIT** policy while retaining
the original CUDA/GDRCopy actuator. Kernel BPF cannot directly enqueue the
CUDA blocking kernel, and a one-shot TSG preempt or bind rejection is not the
same protocol. This would be a userspace-plus-driver BPF policy port, not a
driver-only implementation; unavailable or unverified hook paths remain tasks.

1. **Build and finite smoke:** make architecture flags configurable in a
   separate port; build narrow 575 query/control changes and userspace targets.
   Verify role-to-context/TSG ownership, requested versus effective timeslices,
   GDRCopy flag roundtrip, and cleanup. Use a bounded watchdog that can release
   the owned blocking flag before terminating the workload. Do not run the
   unbounded blocking kernel alone. Record failed original-port runs too.
2. **Preemption microbenchmark:** use identical deterministic LC and long BE
   kernels/data in all three cells; check all output elements, LC dispatch/start
   and completion latency, BE completed work, and actual context switching.
   Include a stateful/non-idempotent BE check, not only an overwrite kernel.
3. **Model experiment:** generate one original pair first (config A's
   VGG/ResNet152). Preserve its **60-second** duration, 100 requests/s per role,
   200 µs preprocessing, and CUDA graphs; do not replace it with the XSched
   five-kernel workload. The original clients allocate host input but leave
   `prepareInput()` empty, so add the same deterministic input initialization to
   all cells and record it as a correctness-instrumentation difference. Check
   outputs against isolated native execution with explicit tolerances, then
   randomize/interleave at least five complete three-cell blocks. Report actual
   completed sample counts alongside LC median/p95/p99, BE throughput, and
   failed trials; requested arrivals are not completed latency samples. Expand
   to remaining original configs only after this pair works.

Do not run `scripts/ae/run_all.sh` as a substitute for that comparison: it also
includes unrelated baselines and precomputed REEF/AMD results. An existing
gpubpf priority run cannot be relabeled as original GPreempt performance.


Both succeeded: `/tmp/gpreempt-575-cpu-check.4UmqI6/gpreempt.o` is 6,232 bytes;
`block-sm120.cubin` is 7,384 bytes. This establishes basic host-wrapper and
blocking-kernel compilation, not driver compatibility or safe execution.

Engineering estimate, **not a guarantee**: 0.5–1 working day for a minimal
575/Blackwell port plus finite smoke if existing GSP timeslice control works;
1–3 working days for a verified repeated three-way model comparison including
the model assets. Driver/GDRCopy or TVM/CUDA incompatibilities can extend this.
The immediate next deliverable is the bounded smoke, not a promised paper-level
speedup. No “infeasible forever” or “already equivalent” conclusion is justified.
