# Device-verifier S0 steady-state result on RTX 5090

Attempt `s0-575-02` completed on NVIDIA driver 575.57.08. The runner accepted
all six pp32 correctness cells and all 60 pp512 timing cells without retry. The
independent analyzer reopened all 66 raw directories and reports
`complete: true`, `run_status: valid`, and `errors: []`. All cells used the
same llama.cpp build 7102 and the verifier-enabled CUDA/LLVM runtime recorded
in `result.json`.

The primary paired effect is
`100 * (STRICT throughput / NO_VERIFY throughput - 1)`. Positive values favor
STRICT. Each tool has ten fixed-seed randomized complete blocks.

| device tool | mean effect | median effect | 95% bootstrap CI of mean |
|---|---:|---:|---:|
| `kernelretsnoop` | -0.0746% | -0.0376% | [-0.7845%, +0.6086%] |
| `threadhist` | +0.0037% | -0.1374% | [-0.4233%, +0.4390%] |

Both intervals include zero. On this workload, neither tool shows a detected
directional steady-state throughput difference between strict admission and
the verification bypass. This is not an equivalence or zero-overhead result:
the frozen plan specified no equivalence margin, used one post-warmup measured
sample per fresh process, and covers only these two programs on this stack.

The instrumented callbacks themselves still have substantial workload-specific
cost. Relative to uninstrumented controls, STRICT throughput is 99.6631% lower
for the full `kernelretsnoop` exit-record stream and 4.0729% lower for the
`threadhist` aggregate. The corresponding NO_VERIFY values are 99.6628% and
4.0744% lower. S0 isolates verifier mode; it does not claim that device
instrumentation is free.

Every STRICT cell records one positive admission timing and exact map
descriptor for the target PID. Every NO_VERIFY cell records one explicit skip
and no admission timing. The analyzer never uses admission time as a throughput
input. It also rederives process identity, command, output, callback counts,
private shared-memory cleanup, driver/boot/UVM/`struct_ops` state, telemetry,
and kernel-log gates from the retained records.

OpenCode with local Qwen3.8-27B independently returned `VERDICT: PASS` for the
completed raw result and claim boundary (session
`ses_f92d4ba46ffe7ZP0JK3f6spU4f`). It noted a nonblocking provenance naming
trap in the runner: Python's `all([])` caused the derived runner field
`timing_positive` to be true for a valid NO_VERIFY cell with zero timing
records. The independent analyzer recomputed that field correctly and did not
trust the runner value. The raw result remains unchanged; the runner was fixed
afterward and its 18 offline tests pass.
